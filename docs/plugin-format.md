# Plugin format

This is the reference for the files a plugin ships and the rules they must pass. It mirrors
`scripts/lib/rules.mjs` and `scripts/validate.mjs`. If this document and the validator ever
disagree, the validator is right; open an issue.

## Package layout

A plugin is a folder under `plugins/<id>/`, where `<id>` is the plugin's id and also its
folder name:

```text
plugins/<id>/
├── manifest.json     # required
├── plugin.js         # required
├── README.md         # required
├── LICENSE           # optional (or LICENSE.md)
└── CHANGELOG.md      # optional
```

No other files are allowed, and there are no subfolders: `plugin.js` is a single file, not a
bundle. Nothing in the folder may be a symbolic link; submit the real file.

## Manifest field reference

`manifest.json` is a JSON object. Unknown top-level fields make it invalid.

| Field | Required | Rule |
| --- | --- | --- |
| `id` | yes | Lowercase letters, digits and hyphens, starting with a letter or digit, up to 64 characters. Must match the folder name. |
| `name` | yes | Non-empty string, up to 160 characters. |
| `version` | yes | A semantic version such as `1.0.0` (optional pre-release or build metadata), up to 64 characters. The app accepts any short string; the directory requires a semantic version so updates can be compared. |
| `apiVersion` | yes | A number: `1` or `2`. |
| `author` | no in the manifest, required to be listed | String, up to 160 characters. The directory refuses to list a plugin without one. |
| `description` | no in the manifest, required to be listed | String, up to 1000 characters. The directory refuses to list a plugin without one. |
| `minAppVersion` | no | A version string such as `2.10.0`, up to 64 characters. |
| `permissions` | no | Array of strings, up to 50 entries, no duplicates. Each must be one of `commands`, `editor`, `ui`, `notes.read`, `net.fetch`, `secrets`. With `apiVersion: 1`, only `commands`, `editor` and `ui` are allowed; the others need `apiVersion: 2`. |
| `allowedHosts` | only with `net.fetch` | Array of unique, exact lowercase hostnames, up to 50 entries. No scheme, port, path, IP address, wildcard or `localhost` label. Required and non-empty when `permissions` includes `net.fetch`; an error if present without it. |
| `commands` | no | Array of up to 50 `{ "id", "label" }` objects. `id` up to 128 characters, `label` up to 200, both non-empty. Command ids must be unique. Declaring any `commands` entries needs the `commands` permission. |
| `instructions` | no | Array of up to 20 strings, each up to 500 characters. Shown as setup and usage steps. |

The directory is stricter than the app in a few places, because the app would otherwise only
fail later, in front of a user:

- `version` must parse as a real semantic version.
- `description` and `author` are required for a plugin to be listed, even though the manifest
  format alone does not require them.
- `allowedHosts` is only accepted together with the `net.fetch` permission, in either
  direction: `net.fetch` without hosts, or hosts without `net.fetch`, are both rejected.
- Declaring `commands` needs the `commands` permission. The app accepts such a manifest but
  then drops every command the plugin registers, which is how a listed plugin once lost all
  of its commands.
- API v1 plugins are limited to `commands`, `editor` and `ui`; the rest of the surface needs
  `apiVersion: 2`. See [docs/api.md](api.md).

## Registry entry reference

`registry.json` holds one entry per listed plugin, generated by `npm run registry -- <id>`
(`scripts/registry-entry.mjs`). Never hand-edit an entry; the command reads the plugin's own
files and writes an entry that mirrors them:

| Field | Meaning |
| --- | --- |
| `id`, `name`, `version`, `description`, `author`, `apiVersion` | Copied from `manifest.json`. Each is required, non-empty, and within the same length limit as the manifest field. |
| `minAppVersion` | Copied from `manifest.json` when present, otherwise omitted. |
| `permissions`, `allowedHosts` | Copied from `manifest.json`, defaulting to `[]` when absent. |
| `files` | `{ "manifest.json": { "sha256": "…" }, "plugin.js": { "sha256": "…" } }`, the SHA-256 of the exact bytes on disk. |
| `path` | Always `plugins/<id>`. |

The validator checks that every mirrored field says exactly what `manifest.json` says, that
both hashes match the files on disk, and that entries are sorted by id (`npm run registry`
keeps them sorted). Every plugin folder needs exactly one registry entry, and every entry
needs exactly one matching folder.

**Version rule:** when a pull request changes a plugin's hashes (its `manifest.json` or
`plugin.js` changed), its `version` must be strictly higher than the version on the base
branch. Both checks enforce it: `validate.yml` with `--base`, and `registry-check.yml` with
`--compare`. See [CONTRIBUTING.md](../CONTRIBUTING.md) for how to pick a new version.

## Folder rules

Checked by `scripts/validate.mjs` without running any plugin code:

- Allowed files: `manifest.json`, `plugin.js`, `README.md`, `LICENSE`, `LICENSE.md`,
  `CHANGELOG.md`. Anything else is rejected.
- `manifest.json`, `plugin.js` and `README.md` are required.
- No folders and no symbolic links inside a plugin's folder.
- `manifest.json` is at most 64 KB.
- `plugin.js` is at most 1 MB. This is meant to keep source readable, not to fit a bundle of
  libraries.
- `plugin.js` must be valid UTF-8 text, with no line longer than 1,000 characters.

## Sharing outside the directory

You do not have to list a plugin here to use it. A plugin package is a folder holding
`manifest.json` and `plugin.js` (the two files can sit at the top of the package or inside one
folder within it), or a `.zip` of that folder. A `README.md` is recommended for whoever reads
the package, but Moldavite installs only the two files it runs and ignores everything else.

Installing this way, from **Settings → Plugins → Install from .zip…** or **Install from
folder…**, uses the app's own limits, which are looser than this directory's because there is
no human review behind them:

- `manifest.json` may be up to 1 MB and `plugin.js` up to 10 MB, both UTF-8, compared to 64 KB
  and 1 MB here.
- A `.zip` may be up to 32 MB with at most 2,000 entries.
- Symbolic links are refused rather than followed, and a package holding more than one plugin
  is refused.

`manifest.json` still has to pass the same validation as an installed plugin, including a
supported `apiVersion` and `minAppVersion`. The confirmation warns that the plugin did not come
from the reviewed directory and shows the SHA-256 of `plugin.js`, so the person installing it
can compare it with what the author published. The plugin is installed turned off, into
`.plugins/<id>/` of the active Forge; installing a folder over an existing id asks the person
to choose **Update** or **Replace** first, and the old approval stops applying because the
files changed.
